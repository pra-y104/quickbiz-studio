# Stage 5 - ordinary tools

Stage 5 adds the eight free tools that make QuickBiz Studio useful before any AI,
credit or payment feature exists. All of them run entirely in the browser: there is
no API call, no upload, no account requirement and no credit charge.

## Delivered scope

| Tool | Route | What it does |
|---|---|---|
| Calculator | `/tools/calculator` | Precedence-aware arithmetic with brackets, unary signs, percent and history |
| Percentage Calculator | `/tools/percentage-calculator` | Share of a value, value as a percentage, increase/decrease, percentage difference |
| Unit Converter | `/tools/unit-converter` | Length, weight, temperature, volume and time, with a full reference list |
| Date Calculator | `/tools/date-calculator` | Days between dates, weekdays, calendar breakdown, add and subtract time |
| Invoice Maker | `/tools/invoice-maker` | Itemised invoice with discount, tax, shipping and a downloaded PDF |
| Quotation Maker | `/tools/quotation-maker` | The same document engine with quotation language and a validity date |
| Word & Character Counter | `/tools/word-counter` | Words, characters, sentences, paragraphs, lines, unique words, reading and speaking time |
| Text Formatter | `/tools/text-formatter` | 21 case, spacing, line and cleanup operations with a live preview and `.txt` download |

Directory: `/tools` lists the live tools, filters by category and searches by name.

## Where the logic lives

```
packages/shared/src/tools/     pure calculation and document logic (tested in node)
apps/web/src/lib/tools/        PDF writer, document layout, download helpers
apps/web/src/components/tools/ tool chrome, result panel, document editor
apps/web/src/pages/tools/      eight tool pages plus the directory
```

Rules that shaped this split:

1. **Calculations are pure and framework-free.** Nothing in `packages/shared/src/tools`
   touches the DOM, so every rule is unit-tested without rendering a page and can be
   reused by the API later.
2. **Money never becomes a float.** Amounts are integer minor units, converted with the
   existing `toMinorUnits` / `formatMoney` helpers. A line total is rounded once, at the
   moment it becomes money.
3. **One document engine.** Invoice and quotation share `computeDocumentTotals`,
   `validateDocumentDraft`, `renderDocumentPdf` and `DocumentMaker`. Only labels and the
   second date differ, so the two documents can never disagree about arithmetic.
4. **The PDF writer has no dependency.** See below.

## Why a hand-written PDF writer

The stage rules forbid unnecessary dependencies and paid services. A PDF library would
add hundreds of kilobytes to a free tool that produces two page layouts, so
`apps/web/src/lib/tools/pdf.ts` writes PDF 1.4 directly:

- base-14 Helvetica with WinAnsi encoding (letters, punctuation, currency symbols),
- transliteration only where WinAnsi has no slot (`₦` becomes `NGN `),
- an exact cross-reference table, one page object per page and `/Length` on every stream,
- a small layout layer that repeats the table header, wraps descriptions, paginates long
  documents and numbers every page.

The tests do not trust it blindly. They parse the generated bytes, resolve every
cross-reference offset to a real object, extract the drawn text from the content stream
and assert the printed totals. That covers the failure that matters: a file that opens
but shows the wrong number.

## Behaviour and edge cases

- **Calculator** never uses `eval` or `new Function`; a tokeniser plus recursive-descent
  parser accepts numbers, `+ − × ÷`, brackets, unary signs and postfix `%`. Division by
  zero, unbalanced brackets, trailing operators and absurdly long input return stable
  error codes with plain-language copy.
- **Percentages** return `null` where maths is undefined (zero base, zero average) and the
  interface says why instead of printing `Infinity`.
- **Temperature** is converted affinely and rejects values below absolute zero.
- **Dates** are parsed strictly as `YYYY-MM-DD` in UTC, so the answer cannot change with
  the device time zone. Month arithmetic clamps to the end of the target month, and
  weekday counts are documented as inclusive of the earlier date.
- **Text statistics** are Unicode-aware: accented, Cyrillic and Arabic words count as
  words, Chinese/Japanese/Thai runs count per character, and emoji count once.
- **Money** is validated before download: required parties, at least one priced line, a
  positive total, a discount within range, tax within range, and a due date that is not
  before the issue date. The download button refuses to produce a broken document.

## Privacy

No tool sends anything to a server. There is no localStorage, sessionStorage or cookie
for documents; the invoice exists only in component state until the PDF is generated on
the device, and the download is an object URL created in the page. The pages say this in
plain language rather than hiding it in a policy.

## Accessibility and mobile

- Every control is labelled; errors use `role="alert"` and `aria-invalid`.
- Results sit in `aria-live="polite"` regions.
- Segmented choices are real radio groups (native keyboard support), not div buttons.
- Tap targets are at least 44 px, inputs are 16 px on mobile, and every layout was built
  mobile-first at 360 px before the desktop grid.
- Motion is a single 180 ms entrance, disabled by the global `prefers-reduced-motion`
  rule.

## Bundle impact

Tool routes are lazy. The initial bundle moved from 483 kB to 487 kB raw (139.7 kB
gzipped); the document engine and PDF writer load only on the document routes
(`document-maker` chunk ~24 kB raw / 8 kB gzipped).

## Deliberately not in this stage

AI generation, provider adapters, credits, wallet, subscriptions, payment gateways,
saved results and history. The catalogue still marks every AI tool `planned` with
`creditCost: null`, so `isToolExecutable()` cannot charge anything.

## Manual setup still required

None for these tools. They work without Supabase, without environment variables and
without a network connection. Supabase configuration remains the separate pending task
documented in `docs/16-supabase-setup.md`.
